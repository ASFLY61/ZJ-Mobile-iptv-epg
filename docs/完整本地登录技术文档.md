## 一、概述与成果

### 1.1 背景

中国移动 OTT 机顶盒(华为 EPG,包名 `com.pukka.ydepg`)的节目单数据由 VSP 服务器(`YOUR_VSP_IP`)提供,访问需要一套完整的认证链。盒子内部由 EPG 应用 + `CMCC_Auth` 认证进程协作完成登录。

最初只能靠 Frida 挂 EPG 进程、从内存里读 JSESSIONID + token 来查节目单(`local_playbill.py`)。本项目的目标是**把整条认证链在本地纯 Python 复现**,彻底摆脱对盒子运行时的依赖。

### 1.2 最终成果

```
STBRegister  →  Digest Challenge  →  Digest Auth  →  ZJLogin  →  QueryPlaybill
   (注册)          (取挑战)            (换 UserToken)  (建会话)      (拉节目单)
```

- 输入仅 3 项:`STBID`、`PASSWORD`(静态 `YOUR_PASSWORD`)、VSP 端口(可自动探测)。
- 实测端到端成功:ZJLogin `retCode=000000000`,节目单拉到 **36 个节目**(中央一套)。
- 全程无需 EPG 登录、无需 Frida、无需实时抓包。

### 1.3 一句话原理

> 认证本质是 **HTTP Digest(MD5, qop=auth-int)** 换 UserToken,再用 UserToken 在 VSP 上 **ZJLogin** 换 JSESSIONID 会话,最后带 JSESSIONID + token 查节目单。唯一的"密钥"是静态设备密码 `YOUR_PASSWORD`,其余全是标准 MD5 运算。

### 2.1 三个角色的关系

```
YOUR_EDS_HOST:PORT   ← 认证入口(EDS),POST 后 307 重定向
        │  307 Location
        ▼
YOUR_VSP_IP:<port>/EPG/XML/...    ← 认证实际处理(STBRegister / Digest)
YOUR_VSP_IP:<port>/VSP/V3/...     ← 业务(ZJLogin / 节目单)
```

> 关键认知:`YOUR_EDS_HOST:PORT` 只是**入口**,所有请求 POST 过去后都会被 **307 重定向**到 `YOUR_VSP_IP` 的某个端口。这个端口就是当前 edsUrl 端口,且**会轮换**(7176–7200)。

## 三、整体流程总览

```
┌─────────────────────────────────────────────────────────────────────┐
│  Step 0  STBRegister                                                 │
│  POST /EDS/STBRegister  body=<STBRegisterReq><STBID>..</..>          │
│  → 307 → YOUR_VSP_IP:<p>/EPG/XML/STBRegister                      │
│  → RsltCode=0, UserID, Password(加密)                              │
├─────────────────────────────────────────────────────────────────────┤
│  Step 1  Digest Challenge                                            │
│  POST /EDS/pub/authentication_initial_challenge_v1  (空 body)        │
│  → 307 → YOUR_VSP_IP:<p>/EPG/XML/...challenge_v1                  │
│  → WWW-Authenticate: Digest realm=..,nonce=..,qop=auth-int          │
├─────────────────────────────────────────────────────────────────────┤
│  Step 2  Digest Authentication                                       │
│  POST /EDS/pub/authentication_initial  + Authorization: Digest ...   │
│  HA1=MD5(user:realm:BASE64(pw))  HA2=MD5(POST:uri:MD5(body))        │
│  response=MD5(HA1:nonce:nc:cnonce:qop:HA2)                          │
│  → 307 → YOUR_VSP_IP:<p>/EPG/XML/authentication_initial           │
│  → StatusCode=0, UserToken, ValidFrom/ValidTo(24h)                  │
├─────────────────────────────────────────────────────────────────────┤
│  Step 3  ZJLogin                                                     │
│  POST YOUR_VSP_IP:<p>/VSP/V3/ZJLogin  body={"userToken":..}       │
│  ★ 零请求头(无 UA / 无 Content-Type / 无 Cookie)                   │
│  → retCode=000000000, JSESSIONID, 新 userToken, subscriberID...     │
├─────────────────────────────────────────────────────────────────────┤
│  Step 4  QueryPlaybillListStcProps                                   │
│  POST YOUR_VSP_IP:<p>/VSP/V3/QueryPlaybillListStcProps?..=1589670010│
│  headers: Cookie:JSESSIONID, authorization:<token>, UA:Huawei-EPG-APK│
│  body: {queryChannel:{channelIDs:[..]}, queryPlaybill:{start,end}}   │
│  → retCode=000000000, channelPlaybills[].playbillLites[]            │
└─────────────────────────────────────────────────────────────────────┘
```

### 步骤一览表

| Step | 方法/URL | 请求体 | 关键请求头 | 成功标志 | 产出 |
|---|---|---|---|---|---|
| 0 | `POST /EDS/STBRegister` | `<STBRegisterReq><STBID>..</..>` | `Content-Type: text/xml` | `STBRegisterRsltCode=0` | UserID、加密 Password |
| 1 | `POST /EDS/pub/authentication_initial_challenge_v1` | 空 | — | 返回 `WWW-Authenticate` | realm/nonce/opaque/algorithm/qop |
| 2 | `POST /EDS/pub/authentication_initial` | `<AuthenticationRequest><STBID>..</..>` | `Authorization: Digest ...` | `StatusCode=0` | **UserToken**(24h) |
| 3 | `POST /VSP/V3/ZJLogin` | `{"userToken":..}` | **零头** | `retCode=000000000` | **JSESSIONID** + 新 token |
| 4 | `POST /VSP/V3/QueryPlaybillListStcProps` | JSON | `Cookie`+`authorization`+`UA` | `retCode=000000000` | 节目单 |

## 四、各步骤详解

### Step 0:STBRegister(设备注册)

**作用**:在服务器登记 STB,激活该设备的认证状态。Digest 前必做,否则报 20244/11302。

**请求**:
```
POST http://YOUR_EDS_HOST:PORT/EDS/STBRegister
Content-Type: text/xml; charset=UTF-8

<STBRegisterReq><STBID>YOUR_STBID</STBID></STBRegisterReq>
```

**响应**(经 307 重定向到 `YOUR_VSP_IP:<port>/EPG/XML/STBRegister`):
```xml
<?xml version="1.0" encoding="UTF-8"?>
<STBRegisterRes>
  <STBRegisterRsltCode>0</STBRegisterRsltCode>
  <Description>Success</Description>
  <UserID>YOUR_USERNAME</UserID>
  <Password>UnpueFds%2BkEb0R%2B7vNsOGg%3D%3D</Password>
</STBRegisterRes>
```

**要点**:
- `STBRegisterRsltCode=0` 表示注册成功。
- `UserID` = 订购用户 ID(后续 Digest 的 username)。
- `Password` 是 **URL 编码的 Base64**(`UnpueFds%2BkEb0R%2B7vNsOGg%3D%3D` → `UnpueFds+kEb0R+7vNsOGg==`),是 AES 加密后的设备密码密文。
- **本方案不需要解密它**——因为我们已知明文是静态的 `YOUR_PASSWORD`(见 §5.4)。
- 注册状态有时效,过期后 Digest 会报 20244,需重新 STBRegister 再 Digest(脚本里 6 次重试循环就是这个逻辑)。

---

### Step 1:Digest Challenge(取挑战)

**作用**:向服务器要 Digest 认证参数(realm/nonce 等)。

**请求**:
```
POST http://YOUR_EDS_HOST:PORT/EDS/pub/authentication_initial_challenge_v1
Content-Type: text/plain; charset=UTF-8

(空 body)
```

**响应**(经 307 重定向到 `YOUR_VSP_IP:<port>/EPG/XML/authentication_initial_challenge_v1`):
```
WWW-Authenticate: Digest realm="YOUR_REALM",nonce="YOUR_NONCE",opaque="",algorithm="MD5",qop="auth-int"
```

**解析出的字段**:
| 字段 | 示例值 | 说明 |
|---|---|---|
| realm | `YOUR_REALM` | 认证域(每次可能不同) |
| nonce | `YOUR_NONCE` | 服务器随机数 |
| opaque | `` (空) | 透传 |
| algorithm | `MD5` | 哈希算法 |
| qop | `auth-int` | **完整性保护**(HA2 要带 body 哈希) |

> `qop=auth-int` 是关键:它决定 HA2 必须包含请求体的 MD5,这是和普通 Digest 最大的区别。

---

### Step 2:Digest Authentication(加密核心)

**作用**:用 STBID + 密码算出 `Authorization: Digest ...` 头,换 UserToken。

**请求**:
```
POST http://YOUR_EDS_HOST:PORT/EDS/pub/authentication_initial
Content-Type: text/xml; charset=UTF-8
Authorization: Digest realm="YOUR_REALM",nonce="YOUR_NONCE",opaque="",algorithm="MD5",qop="auth-int",userid="YOUR_USERNAME",nc="000000001",cnonce="<32位hex>",response="<32位hex>"

<?xml version='1.0' encoding='UTF-8' standalone='yes' ?><AuthenticationRequest><STBID>YOUR_STBID</STBID></AuthenticationRequest>
```

**响应**(经 307 重定向到 `YOUR_VSP_IP:<port>/EPG/XML/authentication_initial`):
```xml
<?xml version="1.0" encoding="UTF-8"?>
<AuthenticationResponse>
  <StatusCode>0</StatusCode>
  <UserToken>YOUR_USERTOKEN</UserToken>
  <ValidFrom>20260918194403</ValidFrom>
  <ValidTo>20260919194403</ValidTo>
</AuthenticationResponse>
```

**要点**:
- `StatusCode=0` 表示认证成功。
- `UserToken` 有效期 24 小时(ValidFrom→ValidTo)。
- **请求体必须字节级精确**:`standalone='yes' ?>` 里 `?>` 前**必须有一个空格**(见 §7.1,这是最大的坑)。
- 注意 body 的 XML 声明用**单引号**(`version='1.0'`),且 `standalone='yes'`。

---

### Step 3:ZJLogin(建会话)

**作用**:用 UserToken 在 VSP 上建立 JSESSIONID 会话。这是从"认证"到"业务"的桥。

**请求**:
```
POST http://YOUR_VSP_IP:<port>/VSP/V3/ZJLogin
(★ 零请求头:无 User-Agent、无 Content-Type、无 Cookie)

{"userToken":"YOUR_USERTOKEN"}
```

**响应**:
```json
{
  "result": {"retMsg": "Successfully", "retCode": "000000000"},
  "jSessionID": "YOUR_JSESSIONID",
  "userToken": "YOUR_USERTOKEN",
  "bossID": "ZHEJIANGMOBILE",
  "subscriberID": "YOUR_USERNAME",
  "profileSN": "YOUR_PROFILE_SN",
  "profileID": "YOUR_USERNAME",
  "RRSAddr": "http://hwltc.tv.cdn.zj.chinamobile.com",
  "subnetID": "YOUR_SUBNET",
  "returnJSessionIdInBody": "true",
  "returnCSessionIdInBody": "true"
}
```

**要点(本步两个致命细节)**:
1. **零请求头**:盒子实抓 ZJLogin 请求头是**空的**。脚本若带上 `User-Agent: Huawei-EPG-APK` 或 `Content-Type` 都会导致 `125023001 Find session failed`。Python 里要显式抑制 urllib 默认 UA(设空串)。
2. **端口必须是当前 edsUrl 端口**:UserToken 的会话绑定在特定 VSP 实例(端口)上,端口不对就 `Find session failed`。端口在 7176–7200 间轮换,脚本自动探测(优先用 Step 2 的 307 落点端口)。
3. 响应里的 `userToken` 是**新 token**(可能与 Step 2 的不同,也可能相同),后续业务请求要用**这个**。
4. `jSessionID` 既在 body 里,也在 `Set-Cookie` 里。

---

### Step 4:QueryPlaybillListStcProps(拉节目单)

**作用**:带 JSESSIONID + token 查指定频道某天的节目单。

**请求**:
```
POST http://YOUR_VSP_IP:<port>/VSP/V3/QueryPlaybillListStcProps?userPlaybillListFilter=1589670010
User-Agent: Huawei-EPG-APK
Cookie: JSESSIONID=YOUR_JSESSIONID
Set-Cookie: JSESSIONID=YOUR_JSESSIONID; Path=/VSP/
authorization: <Step3 返回的 userToken>
Content-Type: application/json; charset=UTF-8

{
  "needChannel": "0",
  "queryChannel": {"channelIDs": ["42329858"], "contentType": "CHANNEL", "isReturnAllMedia": "1"},
  "queryPlaybill": {"count": "100", "endTime": "<当天23:59:59的ms>", "offset": "0", "startTime": "<当天00:00:00的ms>", "type": "1"}
}
```

**响应**:
```json
{
  "result": {"retCode": "000000000", "retMsg": "QueryPlaybillListStcProps successfully!"},
  "channelPlaybills": [
    { "channelID": "42329858", "playbillLites": [ {节目1}, {节目2}, ... ] }
  ]
}
```

**要点**:
- `userPlaybillListFilter=1589670010` 是固定查询过滤参数(抓包所得)。
- `startTime`/`endTime` 是**毫秒时间戳**,按 CST(UTC+8)算当天 00:00:00–23:59:59。
- `channelIDs` 是频道 ID 数组(如 `42329858`=中央一套),完整 119 台见 `channel_ids.json`。
- `Set-Cookie` 作为**请求头**发送是盒子的怪癖(抓包所见),保留以完全对齐。
- 这一步**要带** `User-Agent: Huawei-EPG-APK`(和 ZJLogin 相反)。

## 五、加密 / 解密详解

### 5.1 认证算法:HTTP Digest(MD5, qop=auth-int)

这是标准 HTTP Digest Authentication(RFC 2617)的 **auth-int** 变体。核心是三个 MD5:

```
HA1      = MD5( username : realm : BASE64(password) )
HA2      = MD5( "POST:/EDS/pub/authentication_initial:" + MD5(body) )
response = MD5( HA1 : nonce : nc : cnonce : qop : HA2 )
```

> `qop=auth-int` 使 HA2 必须包含**请求体 MD5**(普通 auth 只算方法:URI)。这是本方案与普通 Digest 的唯一算法差异。

### 5.2 用实测值逐步演算(可复现)

以某次成功运行为例:

**输入**:
- `username = YOUR_USERNAME`
- `realm = YOUR_REALM`
- `password = YOUR_PASSWORD`
- `nonce = YOUR_NONCE`
- `nc = 000000001`
- `cnonce = <MD5(随机整数)>`(32 位 hex)
- `qop = auth-int`
- `body = <?xml version='1.0' encoding='UTF-8' standalone='yes' ?><AuthenticationRequest><STBID>YOUR_STBID</STBID></AuthenticationRequest>`

**① 算 BASE64(password)**:
```
BASE64("YOUR_PASSWORD") = "BASE64(YOUR_PASSWORD)"
```

**② 算 HA1**:
```
HA1 = MD5("YOUR_USERNAME:YOUR_REALM:BASE64(YOUR_PASSWORD)")
    = YOUR_HA1
```

**③ 算 body 的 MD5,再算 HA2**:
```
MD5(body) = <32位hex>
HA2 = MD5("POST:/EDS/pub/authentication_initial:" + MD5(body))
    = YOUR_HA2
```

**④ 算 response**:
```
response = MD5("YOUR_HA1:YOUR_NONCE:000000001:<cnonce>:auth-int:YOUR_HA2")
         = YOUR_RESPONSE
```

**⑤ 拼 Authorization 头**:
```
Authorization: Digest realm="YOUR_REALM",nonce="YOUR_NONCE",opaque="",algorithm="MD5",qop="auth-int",userid="YOUR_USERNAME",nc="000000001",cnonce="<cnonce>",response="YOUR_RESPONSE"
```

> 服务器收到后用自己的 realm/password 重算 HA1→response,与客户端送来的 response 比对,一致即认证通过。

### 5.3 nc / cnonce 的生成(易错点)

- **nc = `000000001`**(9 个字符,不是 8 个!)
  - 反编译 `AuthManagerImpl` 的 `countCN(1)`:先 `Long.toHexString(1)="1"`,长度 1,补零到 8 位再拼上计数,最终得到 9 字符 `000000001`。
  - 写成 8 位 `00000001` 会认证失败。
- **cnonce = `MD5(str(random_int))`**
  - 客户端随机数取一个 31 位随机整数,转字符串再 MD5,得 32 位 hex。
  - 每次请求不同,但服务器不校验其随机性,只要求格式对。

### 5.4 设备密码:静态明文 + AES 密文

- **明文 `YOUR_PASSWORD`**:6 位数字设备密码,**静态不变**。
  - 来源:用 Frida 挂 `CMCC_Auth` 进程,从内存/方法返回值读出明文(见 §6)。
  - 因为静态,直接硬编码进脚本,运行时不再需要盒子。
- **STBRegister 返回的 `Password` 字段**:
  - `UnpueFds%2BkEb0R%2B7vNsOGg%3D%3D`(URL 编码)→ `UnpueFds+kEb0R+7vNsOGg==`(Base64)→ AES 密文。
  - 它和明文 `YOUR_PASSWORD` 是**同一个密码**的两种形态。
  - **本方案不解密它**:Digest 直接用明文 `YOUR_PASSWORD`(先 BASE64)算 HA1,不需要碰这个 AES 密文。
  - (早期曾用 `test_aes.py` 尝试 AES 解密验证一致性,但最终走"直接读明文"的更简路径。)

### 5.5 加密/解密小结

| 环节 | 算法 | 输入 | 输出 | 是否必须 |
|---|---|---|---|---|
| Digest HA1 | MD5 | user:realm:BASE64(pw) | 32hex | 必须 |
| Digest HA2 | MD5 | POST:uri:MD5(body) | 32hex | 必须(auth-int) |
| Digest response | MD5 | HA1:nonce:nc:cnonce:qop:HA2 | 32hex | 必须 |
| cnonce | MD5 | 随机整数 | 32hex | 必须 |
| 设备密码 | AES | 明文 YOUR_PASSWORD | 密文 | **不需要**(已知明文) |
| UserToken/JSESSIONID | 服务器生成 | — | 不透明串 | 透传使用 |

> UserToken 和 JSESSIONID 都是**服务器生成的不透明 token**,客户端不参与其加密,只负责携带。

## 七、踩坑记录

### 7.1 坑一:20244 — Digest body 少一个空格(最大坑,卡最久)

- **现象**:Digest 认证一直返回 20244。
- **根因**:body 的 XML 声明 `standalone='yes' ?>` 里,`?>` 前**必须有一个空格**。本地拼的 body 少了空格,导致 `MD5(body)` 不同 → HA2 不同 → response 不同 → 认证失败。
- **解决**:用 Frida 调盒子自己的 `XMLParseCls.getPostInfo` 实抓精确 body(`get_body.py`),确认 `?>` 前有空格;本地复算 MD5 = `YOUR_BODY_MD5` 与盒子一致后通过。
- **教训**:字节级协议不能靠"看起来一样",必须和参考实现逐字节比对。

### 7.2 坑二:125023001 "Find session failed"(ZJLogin 失败)

- **现象**:ZJLogin 返回 `125023001 Find session failed`。
- **根因(两个,叠加)**:
  1. **端口错**:脚本写死 `7182`(旧 config.json 值),而当前 edsUrl 端口是 `7200`(后实测为 `7183`)。UserToken 会话绑定在特定 VSP 实例上,端口不对就找不到会话。
  2. **多了请求头**:脚本全局注入 `User-Agent: Huawei-EPG-APK` + `Content-Type`,而盒子 ZJLogin 是**零请求头**。
- **解决**:
  - 端口:加 `find_working_port()` 自动探测(优先用 Digest 307 落点端口,再扫 7176–7200)。
  - 请求头:`_raw_post`/`post` 加 `no_ua` 开关,ZJLogin 走 `no_ua=True` 抑制 UA。
- **教训**:VSP 多实例 + 端口轮换,会话与端口绑定;不同接口对请求头的要求不同(ZJLogin 零头,业务请求要 UA)。

### 7.3 坑三:nc 写成 8 字符

- **现象**:Digest 认证失败。
- **根因**:`nc` 应是 9 字符 `000000001`,误写成 8 字符 `00000001`。
- **解决**:按反编译 `countCN(1)` 逻辑,确认 9 字符。

### 7.4 坑四:urllib 不跟随 POST 的 307

- **现象**:手动重定向逻辑缺失,POST 后 307 丢失 body。
- **解决**:`post()` 手动循环跟随 301/302/303/307/308,保留原 body。

### 7.5 坑五:challenge 头解析

- **现象**:`WWW-Authenticate` 值带 `Digest ` 前缀,直接按逗号切分出错。
- **解决**:先 `split(" ",1)[1]` 去掉 `Digest` 前缀再解析字段。

### 7.6 坑六:PowerShell 内联 XML 的 `<`

- **现象**:pwsh 里内联含 `<` 的 XML 报 "The '<' operator is reserved"。
- **解决**:改用 `.py` 文件,不在命令行内联 XML。

### 7.7 坑七:Frida 看不到 EPG 进程

- **现象**:`enumerate_processes()`(122 个)里没有 `com.pukka.ydepg`,但 `ps -A` 有。
- **解决**:EPG 必须**按 pid 直接 attach**(`device.attach(pid)`),不能按名字。

## 结语

整套认证**没有真正的"强加密"**——核心是标准 HTTP Digest(MD5),唯一敏感输入是静态设备密码 `YOUR_PASSWORD`。真正的难点不在算法,而在:

1. **字节级精确**(Digest body 的空格);
2. **请求头差异**(ZJLogin 零头 vs 业务请求要 UA);
3. **端口轮换**(VSP 多实例,会话与端口绑定)。

把这三点吃透,整条链就能在本地纯 Python 稳定复现。
